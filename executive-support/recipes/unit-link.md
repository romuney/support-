# Ссылка на юнит → `id` → `rk` → основные витрины

## Какую задачу решает

Заказчик присылает не название подразделения, а **ссылку**:

```
https://my.tbank.ru/structure/resource/units/e289067b-26b6-44f2-917e-668d1ea65cc5?searchEmployee=68058
```

В ссылке стоит `id` юнита. **В основных витринах этого `id` нет** — там есть
только `rk`, постоянный ключ. Поэтому напрямую по ссылке отфильтровать нельзя,
и попытка искать значение из ссылки среди названий подразделений или среди
`*_rk` не находит ничего: это разные поля.

Между ними ровно один переход, и делается он через справочник юнитов.

## Какие таблицы участвуют

`t-management-unit` — управленческая структура.
`t-functional-unit` — Каталог продуктов (он же продуктовая, он же
функциональная структура).
`t-emp-structure`, `t-functional-role` — куда идём с полученным `rk`.

## Шаг 0. Определить структуру по виду ссылки

Вид ссылки говорит, какая это структура, — угадывать не нужно:

| Ссылка | Структура | Справочник | Поле с `id` |
|---|---|---|---|
| `my.tbank.ru/structure/resource/units/<id>` | управленческая | `t-management-unit` | `management_unit_id` |
| `my.tbank.ru/product-catalog/product/<id>` | Каталог продуктов | `t-functional-unit` | `functional_unit_id` |

`id` — это UUID, последний сегмент пути. Хвост после `?` (например
`?searchEmployee=68058`) к юниту отношения не имеет и отбрасывается.

Ссылка **юридической** структуры сюда не входит: такие приходят редко,
и разбор для них не заведён. Пришла ссылка не из таблицы выше — не подбирай
похожий справочник, скажи, что вид ссылки не распознан, и спроси название
подразделения.

## Шаг 1. Ссылка → `rk`

Управленческая структура:

```sql
select management_unit_rk          -- ключ для шага 2
     , management_unit_nm          -- название, чтобы подписать фильтр
from prod_v_dds.management_unit
where management_unit_id = 'e289067b-26b6-44f2-917e-668d1ea65cc5'
  and valid_to_dttm = '5999-01-01'   -- актуальная версия
  and deleted_flg = 0
```

Каталог продуктов:

```sql
select functional_unit_rk
     , functional_unit_nm
     , management_unit_rk          -- мост в управленческую структуру
from prod_v_dds.functional_unit
where functional_unit_id = 'c5b3a0ac-a44b-4353-9f37-902ef0f5d4c6'
  and valid_to_dttm = '5999-01-01'
  and close_flg = 0                -- юнит не закрыт
  and deleted_flg = 0
```

Ничего не вернулось — это ответ, а не повод искать в другом поле:
либо юнит закрыт или удалён, либо ссылка не из этой структуры. Так и скажи,
а не подставляй похожее.

## Шаг 2. `rk` → сотрудники

Дальше работает уже существующий алгоритм — уровень не угадывается:

- **управленческая структура:** с `management_unit_rk` идём в
  [`find-unit-level.md`](find-unit-level.md). Ключ у нас уже есть, поэтому
  шаг 1 того рецепта сводится к «на каком уровне лежит этот ключ»:

  ```sql
  select distinct management_unit_lvl_num, mapped_management_unit_nm
  from prod_v_emart.mdm_employee_structure_d
  where last_day_flg = 1
    and mapped_management_unit_rk = '<rk из шага 1>'
  ```

  Уровень `N` из результата — и фильтр ставится по `lvl{N}_mapped_management_unit_rk`;

- **Каталог продуктов:** с `functional_unit_rk` идём в `t-functional-role`,
  численность там считается через `count(distinct)`, а ставки — через
  `sum(allocation_prt)`, см. `m-fte-product`.

## Что заказчик обычно имеет в виду под «с детализацией до УС4-УС5»

Уровни управленческой структуры, а не два разных юнита: нужен разрез
по `lvl4_mapped_management_unit_nm` и `lvl5_mapped_management_unit_nm`
внутри найденного юнита. Сам найденный юнит при этом может лежать выше —
на 3 уровне, — и тогда это обычная детализация вниз.

## Чего избегать

1. **Искать значение из ссылки среди `*_rk` или названий подразделений.**
   Это `id`, его нет ни там, ни там. Ровно на этом живой прогон 2026-08-31
   объявил, что юнит «не обнаружился ни по названию, ни по идентификатору»,
   и предложил заказчику самому сказать, где его искать.
2. **Пропускать фильтр версии** `valid_to_dttm = '5999-01-01'` — один юнит
   вернётся несколькими версиями, и всё дальнейшее задвоится.
3. **Забывать `close_flg = 0`** в Каталоге продуктов.
4. **Достраивать соответствие структур по названиям.** Оно задано полем
   `management_unit_rk` в `t-functional-unit`.

## Как проверить результат

Название из шага 1 должно совпасть с тем, что заказчик видит по своей ссылке.
Не совпало — взят не тот справочник либо не та версия.
