# usr_cross_data.head_segments_versions

## Что описывает

Витрина с метриками структуры команды для проекта по здоровью структуры
IT-команд. Если нужно вывести **сегмент руководителя** — это поле
`head_lvl_segment`.

Витрина версионная: у одного `mdm_employee_rk` столько строк, сколько раз
менялись его сегменты, актуальная версия — `valid_to_dttm = '5999-01-01 00:00:00'`.

## Гранулярность строки

Одна строка = одна версия сегмента сотрудника (SCD2).

## Первичный ключ

`mdm_employee_rk` + границы версии `valid_from_dttm` / `valid_to_dttm`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-emp-structure` | `mdm_employee_rk` = `mdm_employee_rk` **и** `valid_to_dttm = '5999-01-01 00:00:00'` |

Готовый джойн к витрине сотрудников:

```sql
left join usr_cross_data.head_segments_versions hs
    on e.mdm_employee_rk = hs.mdm_employee_rk
   and hs.valid_to_dttm = '5999-01-01 00:00:00'
```

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.

| поле | что важно знать |
|---|---|
| `head_lvl_segment` | сегмент руководителя. Именно его выводить, когда просят сегмент |
| `mdm_employee_rk` | ключ сотрудника, связывает с `t-emp-structure` |
| `valid_from_dttm` / `valid_to_dttm` | границы версии |

## Как фильтровать

Обязательный фильтр актуальной версии — иначе строки размножатся на каждую
историческую версию сегмента:

```sql
WHERE valid_to_dttm = '5999-01-01 00:00:00'  -- актуальная версия
```

## Категорически нельзя

1. **Джойнить без фильтра версии.** Без `valid_to_dttm = '5999-01-01 00:00:00'`
   один сотрудник вернётся несколько раз, и всё, что джойнится дальше, задвоится.

## Персональные данные

Сегменты структуры команды; детализированных ПДн сотрудника не содержит.
