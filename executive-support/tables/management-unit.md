# prod_v_dds.management_unit

## Что описывает

Справочник юнитов структуры управления группой компаний: ключ, внутренний
идентификатор, название, родитель, руководитель.

**Зачем он нужен в первую очередь:** это единственное место, где `id` юнита
из ссылки `my.tbank.ru` превращается в `management_unit_rk` — ключ, которым
юнит адресуется в основных витринах. В `t-emp-structure` идентификатора
из ссылки НЕТ, есть только `rk`, поэтому без этого шага ссылку заказчика
использовать нечем. Алгоритм целиком — [`../recipes/unit-link.md`](../recipes/unit-link.md).

## Гранулярность строки

Одна строка = одна версия юнита. Витрина версионная (SCD2): у одного
`management_unit_rk` столько строк, сколько раз менялись его атрибуты.

## Первичный ключ

`management_unit_rk` + `valid_from_dttm`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-emp-structure` | `management_unit_rk` = `mapped_management_unit_rk` либо `lvl{N}_mapped_management_unit_rk` |
| сама с собой (иерархия) | `parent_management_unit_rk` → `management_unit_rk` |
| `t-functional-unit` | `management_unit_rk` — юнит Каталога продуктов знает свой управленческий юнит |

Какое именно поле уровня брать в `t-emp-structure`, решает шаг 1
из [`../recipes/find-unit-level.md`](../recipes/find-unit-level.md):
уровень не угадывается.

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.

| поле | что важно знать |
|---|---|
| `management_unit_rk` | **постоянный** ключ юнита. Им юнит адресуется везде |
| `management_unit_id` | внутренний идентификатор. **Это он стоит в ссылке** `my.tbank.ru/structure/resource/units/<id>` |
| `parent_management_unit_rk` | ключ родительского юнита, по нему строится иерархия |
| `management_unit_nm` | название. Дублируется и меняется — фильтровать по нему нельзя |
| `head_management_position_rk` | ключ позиции руководителя юнита |
| `learning_group_flg` | флаг учебной группы |
| `deleted_flg` | флаг удаления записи из системы-источника |
| `valid_from_dttm` / `valid_to_dttm` | границы версии |

## Как фильтровать

Обязательный фильтр актуальной версии — иначе строки размножатся на каждую
историческую версию юнита:

```sql
WHERE valid_to_dttm = '5999-01-01'  -- актуальная версия
  AND deleted_flg = 0               -- не удалён в источнике
```

## Категорически нельзя

1. **Искать юнит по `management_unit_rk`, взяв значение из ссылки.** В ссылке
   стоит `management_unit_id`, это разные поля.
2. **Работать без фильтра версии.** Без `valid_to_dttm = '5999-01-01'` один
   юнит вернётся несколько раз, и всё, что джойнится дальше, задвоится.
3. **Фильтровать по названию вместо ключа.** Названия дублируются между
   уровнями и меняются со временем.

## Персональные данные

Справочник структуры, персональных данных не содержит. `head_management_position_rk` —
ключ позиции, а не человека.

## Связанные сущности

`t-emp-structure`, `t-functional-unit`, `rc-unit-link`, `rc-find-unit-level`
