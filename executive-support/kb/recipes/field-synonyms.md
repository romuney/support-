# Словарь синонимов: слово заказчика → поле

## Какую задачу решает

Заказчик говорит «стрим», «HQ», «текучка», «сколько людей». Таблица ниже
переводит это в имена полей и фильтры. Точное написание значений всё равно
подтверждается через `select distinct` — см. `kb/process/sql-conventions.md`.

## Какие таблицы участвуют

`t-emp-structure` — если не указано иное.

## Покраска: два поля, а не подразделение

**«Покраска» — жаргон для двух полей-классификаторов специализации.** Заказчик
почти никогда не говорит слово «покраска» целиком: он говорит «HQ», «BigOps»,
«IT-шники», «не IT», а иногда просто «значение». Поля называются по-английски,
и ни слово «покраска», ни «HQ» в описании поля в каталоге не встречаются —
найти их поиском по смыслу невозможно, мост даёт только эта таблица.

| Поле | Значения | Про что |
|---|---|---|
| `emp_specialization_oper_code` | `HQ`, `Line`, `Support` | отношение специализации к операционной деятельности |
| `emp_specialization_it_code` | `IT`, `Digital`, `Non-IT` | отношение специализации к IT-направлению |

**Покраска — это НЕ подразделение.** Вопрос «сколько сотрудников по покраске
HQ» решается фильтром по `emp_specialization_oper_code`, а не поиском «HQ»
среди значений `lvl{N}_mapped_management_unit_nm`. Живой прогон 2026-08-31
пошёл вторым путём: «HQ» дословно не нашлось, и вместо ответа заказчик
получил `lvl3_mapped_management_unit_nm in ('Финансы', 'Human Capital',
'Технологии, Безопасность, Операции')` — подразделения, подобранные
по смыслу. Запрос выполнится и вернёт неверные цифры молча.

### BigOps — старое название, и оно требует вопроса

`BigOps` (он же `Big Ops`, `Non-HQ`) — прежнее общее имя для всего, что
не HQ, то есть для `Line` и `Support` вместе. Отдельного значения `BigOps`
в поле НЕТ.

Просят «выгрузку по BigOps» — **задай один вопрос**: какая покраска нужна,
`Line`, `Support` или обе. Это та же развилка, что с шестью флагами
руководителя: молча взять оба значения или молча одно — значит отдать
правдоподобные и неверные цифры, а разницы заказчик не увидит.

Спросили прямо про `HQ`, `Line`, `Support`, `IT`, `Digital` или `Non-IT` —
вопроса нет, значение названо однозначно.

## Значения `active_type_nm`

13 значений. Если заказчик употребил любое из правых формулировок — фильтр
по `active_type_nm`.

| Значение в поле | Как говорят |
|---|---|
| `Активная` | активные сотрудники, действующий персонал |
| `Стажеры` | стажёры, стажировка, интерны, участники программы стажировки |
| `Декрет` | декрет, отпуск по уходу за ребёнком |
| `Подрядчики` | подрядчики, контракторы, внешние исполнители |
| `Мобилизованные` | мобилизованные, сотрудники по мобилизации |
| `Прогульщики` | прогульщики, неявки по дисциплине |
| `На оформлении` | оформление, трудоустройство, кандидаты на оформлении |
| `Кандидаты в учебных юнитах` | кандидаты, учебные юниты, стажёры-кандидаты |
| `POS-агент` | POS-агенты, агенты на точках, полевые агенты |
| `Амбассадор` | амбассадоры, бренд-амбассадоры, евангелисты |
| `Автор стратегий` | авторы стратегий, стратегические консультанты |
| `Клексы` | клексы, Kleksy |
| `Разовые услуги` | разовые услуги, разовые работы, временные услуги |

## Чего избегать

1. **Определять стажёров через `position_nm`, `legal_unit_nm` или `grade`.**
   Только `active_type_nm = 'Стажеры'`.
2. **Искать покраску среди названий подразделений.** `HQ`, `Line`, `Support`,
   `BigOps` — значения `emp_specialization_oper_code`, и в управленческой
   структуре их нет. Не нашлось дословно в поле подразделения — это признак
   неверного поля, а не повод подобрать подразделение по смыслу.
3. **Использовать значение из словаря без `select distinct`.** Словарь даёт
   имя поля, а не гарантию написания значения.
4. **Угадывать, какой из флагов руководителя нужен.** Их шесть — при отсутствии
   уточнения задаётся один вопрос.
5. **Раскладывать `BigOps` самому.** Это два значения, и какое нужно —
   знает только заказчик.

## Как проверить результат

Значение из фильтра встречается в результате `select distinct` по этому полю.
Пустая выборка при непустом фильтре — почти всегда неточное написание значения,
а не отсутствие данных.
