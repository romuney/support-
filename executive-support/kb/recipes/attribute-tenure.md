# Стаж в атрибуте: gaps & islands

## Какую задачу решает

Считает, сколько дней сотрудник провёл в конкретном значении атрибута
(специализация, грейд, должность, подразделение, руководитель) в рамках
последнего найма — с корректной обработкой случая «уходил и вернулся».

Определение метрики — `m-attribute-tenure`.
Готовый SQL — [`attribute-tenure.sql`](attribute-tenure.sql), версия v2.1.

## Какие таблицы участвуют

`t-emp-structure` — единственный источник. Витрина подневная и непрерывная:
ровно одна строка на `(mdm_employee_rk, business_dt)`. Алгоритм построен
на этом свойстве.

Change-таблицы для стажа не используются.

## Параметры шаблона

| Параметр | Обязательный | Смысл |
|---|---|---|
| `attr_column` | да | имя колонки атрибута, например `emp_specialization_desc` |
| `attr_value` | да | целевое значение, например `'Бизнес-аналитик BI'` |
| `mart_table` | нет | витрина, по умолчанию `prod_v_emart.mdm_employee_structure_d` |
| `mart_min_date` | нет | дата старта витрины, по умолчанию `'2021-01-01'` |
| `only_current` | нет | `true` — только те, кто в атрибуте сейчас; `false` — все в рамках последнего найма |
| `last_hire_from` / `last_hire_to` | нет | когортное окно по дате последнего найма |

## Порядок связывания

1. **Последний найм.** `max(company_hire_dt)` на сотрудника — обнуляет стаж
   при ре-найме.
2. **Когорта (опционально).** Фильтр `last_company_hire_dt between X and Y`
   поверх результата шага 1 — оставляет тех, чей **последний** найм попал в окно.
3. **Подневная история.** Все `business_dt` в целевом значении атрибута.
   Джойн по **двум** полям: `(mdm_employee_rk, company_hire_dt)`.
4. **Острова.** Разрыв определяется через `lag(business_dt) = business_dt - 1 day`.
5. **Sanity-check.** `days_in_island` обязан равняться
   `(island_end_raw - island_start_raw + 1)`.
6. **Корректировка границ.** Начало: если остров упирается в `mart_min_dt`
   и найм был раньше — берётся `company_hire_dt`. Конец: активный — `mart_max_dt`,
   уволенный — `company_fire_dt`.
7. **Длительность.** `period_end_dt - period_start_dt + 1`, границы включительные.
8. **Итог.** Сумма длительностей островов плюс QA-метрики.

## Чего избегать

1. **Джойн только по `mdm_employee_rk`** без `company_hire_dt`. Размножает строки
   при ре-наймах — причина №1 «однодневных островов» и завышенного стажа.
2. **Когорта через `where company_hire_dt in X`** в исходной таблице вместо
   фильтра поверх `last_hire`. Даст «когда-либо нанимался в окне» вместо
   «последний найм в окне».
3. **Упрощение до `min/max(business_dt)` на сотрудника.** Категорически нельзя
   без явного подтверждения, что перерывов в атрибуте не бывает: перерыв попадёт
   в стаж.
4. **Атрибуты на `last_day_flg = 1`** в блоке `employee_info` — потеряются
   уволенные. Берутся на дату найма.

## Как проверить результат

Обе QA-колонки в выводе обязаны быть нулём:

| Колонка | Что значит ненулевое значение |
|---|---|
| `_qa_broken_islands` | где-то джойн без `company_hire_dt`, строки размножены |
| `_qa_max_overcount` | на сколько дней максимально завышен остров |

Если не ноль — ошибка в SQL, а не в данных. Искать джойн без второго поля.

## Варианты вызова

```sql
-- стаж в специализации, текущие
{{ render(attr_column='emp_specialization_desc', attr_value='Бизнес-аналитик BI') }}

-- стаж в грейде
{{ render(attr_column='grade_nm', attr_value='Senior') }}

-- стаж в департаменте, включая ушедших из него, но остающихся в компании
{{ render(attr_column='department_nm', attr_value='HR-аналитика', only_current=false) }}

-- стажировка 2025: последний найм в 2025, включая тех, кто уже не стажёр
{{ render(
    attr_column='active_type_nm',
    attr_value='Стажеры',
    last_hire_from='2025-01-01',
    last_hire_to='2025-12-31',
    only_current=false
) }}
```

Jinja-синтаксис — для Superset и Proteus. Для интерпретатора GP берётся
plain-версия из того же файла: значения подставляются вручную, блок
`only_current` оставляется или убирается по задаче.
