# hrmart.summary_evaluation

## Что описывает

Итоговые годовые оценки сотрудников (ревью).

## Гранулярность строки

Не подтверждено. По аналогии с `t-employee-profession` (тот же паттерн SCD2
через `valid_to_dttm`) вероятно одна строка = одна версия оценки сотрудника
за период, но это предположение — уточнить у владельца витрины перед тем,
как считать по ней численность или агрегаты.

## Первичный ключ

Не подтверждено — уточнить у владельца витрины.

## Ключи для связывания

Ключ связи с `t-emp-structure` не подтверждён. По аналогии с остальными
атрибутными таблицами ожидание — `mdm_employee_rk`, но это домысел, а не
проверенный факт: перед использованием свериться через `select distinct`
и с владельцем витрины.

## Срез атрибутов

**Обязательный фильтр актуальной версии:**

```sql
WHERE valid_to_dttm = '5999-01-01'
  AND deleted_flg = 0
```

Без этого фильтра строка сотрудника размножится на все исторические версии
оценки — тот же паттерн, что и в `t-employee-profession`.

## Период и глубина истории

Не заполнено — уточнить у владельца витрины.

## Как обновляется

Не заполнено — уточнить у владельца витрины.

## Категорически нельзя

1. **Забыть фильтр `valid_to_dttm = '5999-01-01' and deleted_flg = 0`** —
   размножение строк по историческим версиям оценки.

## Персональные данные

Итоговая оценка сотрудника — персонализированная и чувствительная запись.
В выгрузки не попадает адресно ни в каком виде; агрегаты по подразделению —
только после согласования с владельцем витрины. Запрос по конкретному
сотруднику — эскалация руководителю, см. `kb/process/routing.md`.

## Связанные сущности

`t-emp-structure`
