# prod_v_hrmart.mdm_employee_attendance

## Что описывает

Данные табеля посещения: рабочие дни, больничные, отпуска, командировки,
декреты и прочие типы присутствия и отсутствия по дням. Используется для
подготовки статистических и HR-отчётов: например, средняя продолжительность
больничного, количество дней в командировках, количество дней в отпуске.

## Гранулярность строки

Одна строка = один сотрудник × один день.

Данные приведены к одному табелю на сотрудника в день ранжированием
из `TUNING.ATTENDANCE_TYPE_RANK`. Для сотрудников с несколькими юридическими
позициями берётся основная (`main_legal_position_flg = 1`).

## Первичный ключ

`mdm_employee_rk` + `attendance_dt`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-emp-structure` | `mdm_employee_rk` + `attendance_dt = business_dt` |

Связка по дате обязательна: без неё строки размножатся на каждый день истории
сотрудника.

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.
Здесь только смысловая разметка, которой в DD нет.

| поле | тип среза | что важно знать |
|---|---|---|
| `mdm_employee_rk` | постоянный | ключ сотрудника |
| `attendance_dt` | партиция | дата посещения. Джойн со витриной сотрудников — `attendance_dt = business_dt` |
| `attendance_type_dk` / `attendance_type_desc` | на дату | код и описание типа: рабочий день, больничный, отпуск. Точные значения — через `select distinct` |
| `attendance_group_nm` | на дату | группа типов, укрупнение над `attendance_type_desc` |
| `ad_login` | атрибут | ПДн, наружу не отдаётся |
| `source_system_cd` | атрибут | система-источник, одни и те же дни приходят из разных систем |
| `etl_deleted_flg` | флаг | технический флаг удаления строки ETL-процессом |

## Как фильтровать

Обязательный фильтр:

```sql
WHERE etl_deleted_flg = 0  -- технический флаг удаления
```

## Как обновляется

Приоритет источников: ТВФМ — данные до двух недель, 1C — старше двух недель.

## Категорически нельзя

1. **Джойнить без условия по дате** — размножение строк.
2. **Использовать значения `attendance_type_desc` без проверки.** Перед фильтром
   обязателен `select distinct attendance_type_desc`: написание типов не угадывается.
3. **Опускать `etl_deleted_flg = 0`** — в выборку попадут технически удалённые
   строки.

## Персональные данные

Больничные и отсутствия — чувствительная категория. В выгрузки не попадают
ни сами диагнозы, ни персональная привязка: только агрегаты по подразделениям
и суррогатные ключи.
