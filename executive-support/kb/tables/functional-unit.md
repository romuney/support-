# prod_v_dds.functional_unit

## Что описывает

Справочник юнитов Каталога продуктов (КП) — он же продуктовая, он же
функциональная структура. Ключ, внутренний идентификатор, название, родитель,
тип юнита, руководящая роль.

Как и управленческий справочник, нужен прежде всего для перевода `id`
из ссылки в `rk`: ссылка `my.tbank.ru/product-catalog/product/<id>` несёт
`functional_unit_id`, а работать дальше можно только с `functional_unit_rk`.
Алгоритм — [`../recipes/unit-link.md`](../recipes/unit-link.md).

**Здесь же лежит мост между двумя структурами:** поле `management_unit_rk`
говорит, какому управленческому юниту соответствует юнит КП. Это
единственное место, где связь задана явно, и достраивать её по названиям
не нужно.

## Гранулярность строки

Одна строка = одна версия юнита КП. Витрина версионная (SCD2).

## Первичный ключ

`functional_unit_rk` + `valid_from_dttm`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-functional-role` | `functional_unit_rk` — роли и аллокации на продукте |
| `t-management-unit` | `management_unit_rk` — соответствующий управленческий юнит |
| сама с собой (иерархия) | `parent_functional_unit_rk` → `functional_unit_rk` |

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.

| поле | что важно знать |
|---|---|
| `functional_unit_rk` | **постоянный** ключ юнита КП |
| `functional_unit_id` | внутренний идентификатор. **Это он стоит в ссылке** `my.tbank.ru/product-catalog/product/<id>` |
| `parent_functional_unit_rk` | ключ родительского юнита КП |
| `functional_unit_nm` | название. Фильтровать по нему нельзя — см. «Категорически нельзя» |
| `functional_unit_type_cd` | код типа юнита КП |
| `head_functional_role_rk` | ключ роли руководителя в КП |
| `management_unit_rk` | мост в управленческую структуру |
| `close_flg` | **флаг закрытого юнита.** Закрытые в актуальную выборку не идут |
| `abm_applicable_flg` | принадлежность юнита к расчёту P&L |
| `deleted_flg` | флаг удаления записи из системы-источника |
| `valid_from_dttm` / `valid_to_dttm` | границы версии |

## Как фильтровать

Актуальный открытый юнит — **три условия, и все обязательны**:

```sql
WHERE valid_to_dttm = '5999-01-01'  -- актуальная версия
  AND close_flg = 0                 -- юнит не закрыт
  AND deleted_flg = 0               -- не удалён в источнике
```

`close_flg` здесь отличает эту витрину от управленческой: в КП юниты
закрывают, и закрытый юнит остаётся в справочнике живой актуальной версией.
Без фильтра он попадёт в выборку наравне с действующими.

## Категорически нельзя

1. **Искать юнит по `functional_unit_rk`, взяв значение из ссылки.** В ссылке
   стоит `functional_unit_id`.
2. **Работать без фильтра версии** — задвоение по историческим версиям.
3. **Забывать `close_flg = 0`** — в выборку попадут закрытые продукты.
4. **Достраивать соответствие с управленческой структурой по названиям.**
   Оно задано полем `management_unit_rk`.

## Персональные данные

Справочник структуры, персональных данных не содержит.
