# prod_v_hrmart.mdm_employee_education

## Что описывает

Сведения об образовании: законченное образование с дипломами и текущее обучение
(студенты, академический отпуск).

## Гранулярность строки

Одна строка = одна запись об образовании. **У одного сотрудника записей столько,
сколько образований он внёс** — по числу дипломов.

## Первичный ключ

`mdm_employee_rk` + запись об образовании. Уникальности по сотруднику нет.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-emp-structure` | только `mdm_employee_rk` |

**Без `business_dt`.** Образование не подневное: добавление условия по дате
обнулит выборку.

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.
Здесь только смысловая разметка, которой в DD нет.

Таблица не подневная: у сотрудника N записей об образовании, поэтому все поля —
атрибуты записи, а не среза на дату. Джойн без `business_dt`.

| поле | роль | что важно знать |
|---|---|---|
| `mdm_employee_rk` | ключ | на одного сотрудника несколько строк, `count(distinct)` обязателен |
| `education_status_nm` | фильтр | статус обучения, 6 значений (см. ниже) |
| `source_table_nm` | фильтр | `educationdocuments` — дипломы, `educationinfo` — анкетные данные. Смешивать нельзя |
| `deleted_flg` | служебный флаг | 0 = активная запись, фильтр обязателен |
| `validation_flg` / `scan_flg` | служебный флаг | подтверждение записи и наличие скана, не характеристика образования |

### Значения `education_status_nm`

«Законченное образование», «Студент очного отделения», «Студент заочного
отделения», «Студент очно-заочного отделения», «В академическом отпуске»,
«Неоконченное высшее образование».

Точное написание подтверждается через `select distinct` перед фильтром.

## Фильтр по умолчанию

`deleted_flg = 0` — обязателен всегда. Без него в выборку попадут удалённые записи.

## Категорически нельзя

1. **Джойнить с `business_dt`** — образование не привязано к дате.
2. **Забывать `deleted_flg = 0`.**
3. **Считать `count(*)` как численность** — это число дипломов. Для людей —
   `count(distinct mdm_employee_rk)`. Число дипломов на сотрудника считается
   окном: `count(*) over (partition by mdm_employee_rk)`.

## Персональные данные

Реквизиты диплома (`document_no`, `document_series`) — персональные данные,
для их выгрузки нужно согласование доступа. Учебное заведение и год окончания
в связке с ФИО тоже идентифицируют человека, и правило то же.

Запрета нет, есть требование согласовать: поле остаётся в составе файла
с пометкой 🔒, см. [`../process/export-playbook.md`](../process/export-playbook.md).
Агрегат без привязки к людям согласования не требует и остаётся самым
быстрым путём, когда он решает задачу.
