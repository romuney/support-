# prod_v_emart.mdm_employee_structure_d

## Что описывает

Основная витрина по сотрудникам: человек и его основная позиция на каждый день.
Управленческая структура, специализация, грейд, статус, флаги найма и увольнения.
Используется для управленческой отчётности, численности, найма и оттока.

## Гранулярность строки

Одна строка = один сотрудник × один календарный день.

Витрина **подневная и непрерывная**: на каждый день существования сотрудника
в компании есть ровно одна строка. Это свойство используется алгоритмом
gaps & islands (см. `rc-attribute-tenure`) — без него расчёт стажа неверен.

## Первичный ключ

`mdm_employee_rk` + `business_dt`. Партиционирование — по `business_dt`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-legal-position` | `mdm_employee_rk` + `business_dt` |
| `functional_role_d` | `mdm_employee_rk` + `business_dt` |
| `mdm_employee_attendance` | `mdm_employee_rk` + `attendance_dt = business_dt` |
| `mdm_employee_education` | только `mdm_employee_rk` — образование не подневное |
| change-таблицы | `mdm_employee_rk` + `change_dt = business_dt` |

**Связывать только по ключам `*_rk`.** Джойн по текстовым полям `*_nm` запрещён:
названия дублируются, меняются, отличаются регистром и пробелами. Ключи есть
для всех уровней структуры (`lvl{N}_mapped_management_unit_rk`, `lvl{N}_legal_unit_rk`)
и для сотрудника (`mdm_employee_rk`).

## Поля

Состав полей, типы и описания — в Data Detective, ключ `dd_urn` в реестре.

Имена полей, названные ниже, — из каталога, и при расхождении прав он, а не
эта статья: правку вносим сюда, а не в ответ.
Здесь только то, чего в DD нет: как поле ведёт себя во времени и какие поля
нельзя путать между собой.

### Тип среза

Свойство, определяющее, можно ли фильтровать по полю за период. В DD не описано,
а без него метрика считается неверно.

| тип среза | что значит | примеры полей |
|---|---|---|
| постоянный | не меняется за всё время | `mdm_employee_rk` |
| партиция | дата строки | `business_dt` |
| на дату | значение атрибута в этот день, историческое | структура, грейд, специализация, `active_type_nm`, флаги численности |
| событие | 1 только в день события, за период суммируется | `company_hire_flg`, `candidate_transfer_flg`, `internal_transfer_flg` |
| флаг | служебный признак строки, не атрибут сотрудника | `last_day_flg`, `last_day_of_month_flg` |
| атрибут | значение-константа в строке | `company_hire_dt`, `company_fire_dt` |

Поля-события фильтруются по `business_dt`, а **не** по `company_hire_dt` /
`company_fire_dt` — см. «Категорически нельзя».

### Поля, которые путают

| берём | не берём | почему |
|---|---|---|
| `lvl{N}_mapped_management_unit_nm/_rk`, N = 3..13 | `lvl{N}_management_unit_nm` | немаппированные уровни не годятся для управленческой иерархии; уровни 1 и 2 игнорируются |
| `lvl{N}_legal_unit_nm/_rk`, N = 1..10 | — | в юридической структуре значимы все уровни |
| `active_employee_flg` | `legal_employee_flg` | разные численности: `m-active-headcount` и `m-legal-headcount` |
| `active_type_nm = 'Стажеры'` | `position_nm`, `grade` | стажёры определяются только по типу активности |
| `*_rk` | `*_nm` | джойн по названиям запрещён |

Точное написание значений перед фильтром подтверждается через `select distinct`,
состав полей — через `get_table_info`. Поля, которого нет в ответе инструмента,
не существует, даже если оно упомянуто здесь.

### Значения `active_type_nm`

`Активная`, `Стажеры`, `Декрет`, `Подрядчики`, `Мобилизованные`, `Прогульщики`,
`На оформлении`, `Кандидаты в учебных юнитах`, `POS-агент`, `Амбассадор`,
`Автор стратегий`, `Клексы`, `Разовые услуги`.

Стажёры определяются **только** через `active_type_nm = 'Стажеры'`. Поля
`position_nm`, `legal_unit_nm`, `grade` для этого не применяются.

## Срез атрибутов

Атрибуты — на дату строки (`business_dt`), то есть исторические.

Для актуального состояния используется `last_day_flg = 1`, а **не**
`business_dt = current_date - 1`: витрина может обновиться с задержкой, и
`current_date - 1` окажется пустым. `last_day_flg = 1` всегда указывает
на последний загруженный день.

`last_day_flg = 1` фильтрует **ровно один день**. Для периодов (найм, отток,
динамика) применяется диапазон по `business_dt` без `last_day_flg`.

## Период и глубина истории

Витрина начинается с 2021-01-01. Границы получаются запросом
`select min(business_dt), max(business_dt)` — в шаблоне стажа они нужны
для корректировки границ островов.

## Как обновляется

Ежедневно, с возможной задержкой. Актуальность = `last_day_flg = 1`.

## Категорически нельзя

1. **Джойнить по `*_nm`** вместо `*_rk`.
2. **Использовать `last_day_flg = 1` для периода** — отфильтрует один день.
   Отток за 2026 год с `last_day_flg = 1` вернёт почти ноль.
3. **Фильтровать потоки по `company_hire_dt` / `company_fire_dt`.** Найм, отток
   и переводы фильтруются по `business_dt`: уволенный не показывается на текущую
   дату, его последняя строка имеет `business_dt` = дата увольнения.
4. **Брать уровни 1 и 2 управленческой структуры** — они игнорируются, поиск
   начинается с `lvl3`.
5. **Использовать немаппированные поля `lvl{N}_management_unit_nm`** вместо
   `lvl{N}_mapped_management_unit_nm` для управленческой иерархии.
6. **Считать стаж в атрибуте через `company_hire_dt`** или через change-таблицы —
   только gaps & islands, см. `rc-attribute-tenure`.
7. **Брать атрибуты на `last_day_flg = 1` в когортном анализе** — уволенные
   потеряются, потому что записи с этим флагом у них нет.
8. **Складывать флаги найма как `SUM(f1 + f2 + f3)`** — двойной счёт, нужен
   отдельный `FILTER` на каждый флаг, см. `m-hiring`.

## Персональные данные

Витрина содержит ПДн: `full_nm` (ФИО), `ad_login`, и в связанных источниках —
паспортные и страховые реквизиты. **В выгрузки они не попадают никогда**, даже
если заказчик настаивает и у него есть доступ. Наружу отдаются только
суррогатные ключи (`mdm_employee_rk`) и роли. Запрос ПДн — эскалация
руководителю группы, см. `kb/process/routing.md`.

## Известные пробелы данных

- **Приёмы из государственных органов.** Витрина не содержит признака перехода
  из гос. структуры — такие сотрудники в `company_hire_flg` и статистике найма
  видны как обычный приём, без источника. Спрашивают о доле или числе таких
  переходов — прямо говорим, что источник приёма здесь не выделен, а не
  подставляем 0 или домысленную цифру. См.
  `cases/2026-08-18-emp-structure-no-govagency-hires.md`.
