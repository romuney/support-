# sdp_itsa_zup.disciplinary_sanction

## Что описывает

Дисциплинарные взыскания сотрудников.

## Гранулярность строки

Не подтверждено — уточнить у владельца витрины.

## Первичный ключ

Не подтверждено — уточнить у владельца витрины.

## Ключи для связывания

Ключ связи с `t-emp-structure` не подтверждён — уточнить у владельца
витрины перед использованием. Ожидание по аналогии с остальными
атрибутными таблицами — `mdm_employee_rk`, но это домысел.

## Срез атрибутов

**Обязательный фильтр:**

```sql
WHERE deleted_flg = false
  AND posted_flg = true
```

Без `posted_flg = true` в выборку попадут неподтверждённые/черновые записи
о взыскании.

## Период и глубина истории

Не заполнено — уточнить у владельца витрины.

## Как обновляется

Не заполнено — уточнить у владельца витрины.

## Категорически нельзя

1. **Забыть один из двух фильтров** (`deleted_flg = false`, `posted_flg = true`) —
   удалённые или неподтверждённые взыскания попадут в выборку.

## Персональные данные

Дисциплинарное взыскание — персонализированная и юридически чувствительная
запись. В выгрузки не попадает адресно ни в каком виде, включая
суррогатный ключ без явного согласования. Запрос по конкретному сотруднику
или подразделению — эскалация руководителю, см. `kb/process/routing.md`.
