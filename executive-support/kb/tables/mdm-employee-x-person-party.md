# emart.mdm_employee_x_person_party

## Что описывает

Связь между сотрудником (единый сотрудник MDM) и клиентом ФЛ (person_party).
Таблица отвечает на вопрос: является ли сотрудник клиентом банка и по каким продуктам.

## Гранулярность строки

Одна строка = одна связь сотрудника с клиентом на момент времени.

Возможны несколько строк на одного сотрудника:
- Несколько клиентов (например, сотрудник является клиентом по разным продуктам)
- Одна связь с разными периодами действия (valid_from_dttm – valid_to_dttm)

## Первичный ключ

Логический ключ: `mdm_employee_rk` + `party_rk` + `valid_from_dttm`.

## Ключи для связывания

| С чем | По каким полям |
|---|---|
| `t-emp-structure` | `mdm_employee_rk` |
| `t-legal-position` | `mdm_employee_rk` |
| Другие витрины сотрудников | `mdm_employee_rk` |

**Важно:** `party_rk` (или `siebel_id`) — это идентификатор клиента в CDM.
Для получения деталей клиента джойнитесь с витринами клиента по этому ключу.

## Поля

### Ключевые поля

| Поле | Тип | Описание |
|---|---|---|
| `mdm_employee_rk` | key | Суррогатный ключ сотрудника |
| `party_rk` | key | Суррогатный ключ клиента (party), также известен как `siebel_id` |
| `valid_from_dttm` | timestamp | Начало периода действия связи |
| `valid_to_dttm` | timestamp | Окончание периода действия связи |
| `deleted_flg` | flag | Флаг удалённой связи |
| `fire_flg` | flag | Флаг увольнения сотрудника |

### Флаги и их значение

| флаг | значение | что означает |
|---|---|---|
| `deleted_flg` | 0 | Связь активна |
| `deleted_flg` | 1 | Связь удалена — между сотрудником и клиентом **нет связи** в указанный период |
| `fire_flg` | 0 | Сотрудник работает в компании в указанный период |
| `fire_flg` | 1 | Сотрудник уволен — связь с клиентом есть, но сотрудник **не работал** в компании в указанный период |

## Как фильтровать

**Обязательные фильтры для получения активных связей работающих сотрудников:**

```sql
WHERE deleted_flg = 0  -- только активные связи
  AND fire_flg = 0     -- только работающие сотрудники
```

### Почему нужны оба фильтра

1. **`deleted_flg = 0`** — отфильтровывает удалённые связи. Если `deleted_flg = 1`, 
   то между сотрудником и клиентом в указанный период `valid_from_dttm – valid_to_dttm` 
   **нет связи**.

2. **`fire_flg = 0`** — отфильтровывает связи с уволенными сотрудниками. Если 
   `fire_flg = 1`, то связь между сотрудником и клиентом существует, но сотрудник 
   в компании в заданный период `valid_from_dttm – valid_to_dttm` **не работал**.

### Категорически нельзя

1. **Использовать фильтрацию только по `main_flg`** — это приводит к дублям. 
   Для корректного результата обязательно используйте оба фильтра: 
   `deleted_flg = 0` **и** `fire_flg = 0`.

2. **Игнорировать период действия связи** — связь действительна только в пределах 
   `valid_from_dttm – valid_to_dttm`. Для среза на дату используйте:
   ```sql
   WHERE valid_from_dttm <= :cutoff_date
     AND (valid_to_dttm >= :cutoff_date OR valid_to_dttm IS NULL)
   ```

3. **Считать сотрудника клиентом без проверки флагов** — запись в таблице означает 
   лишь факт связи, но не её актуальное состояние.

## Примеры запросов

### Является ли сотрудник клиентом банка (на текущую дату)

```sql
SELECT 
    mdm_employee_rk,
    party_rk,
    valid_from_dttm,
    valid_to_dttm
FROM prod_v_emart.mdm_employee_x_person_party
WHERE deleted_flg = 0
  AND fire_flg = 0
  AND valid_from_dttm <= CURRENT_DATE
  AND (valid_to_dttm >= CURRENT_DATE OR valid_to_dttm IS NULL)
```

### По каким продуктам сотрудник является клиентом

```sql
SELECT 
    ep.mdm_employee_rk,
    ep.party_rk,
    -- Детали клиента из других витрин по party_rk
    c.client_name,
    c.product_type
FROM prod_v_emart.mdm_employee_x_person_party ep
JOIN <client_vitryna> c ON c.party_rk = ep.party_rk
WHERE ep.deleted_flg = 0
  AND ep.fire_flg = 0
```

### Сколько сотрудников являются клиентами банка

```sql
SELECT 
    COUNT(DISTINCT mdm_employee_rk) AS employee_clients_count
FROM prod_v_emart.mdm_employee_x_person_party
WHERE deleted_flg = 0
  AND fire_flg = 0
```

## Период и глубина истории

История хранится с момента создания связи. Границы периодов определяются полями 
`valid_from_dttm` и `valid_to_dttm`. Для актуального состояния используйте 
фильтры по дате среза.

## Как обновляется

Обновляется по мере изменения связей между сотрудниками и клиентами. Частота 
обновления зависит от источника данных.

## Связанные сущности

`t-emp-structure`, `t-legal-position`, клиентские витрины (по `party_rk`)

## Персональные данные

Таблица содержит связку между сотрудником и клиентом. При джойне с клиентскими 
витринами могут быть получены ПДн клиента. Соблюдайте требования к обработке 
ПДн, см. `kb/process/routing.md`.
