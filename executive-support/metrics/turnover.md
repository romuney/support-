# Текучесть

## Определение одной фразой

Доля уволившихся за период от средней численности за тот же период, в процентах.

## Формула

```
текучесть = уволенные за период / средняя численность за период × 100
```

Средняя численность за месяц:

```
СЧ за январь = (численность на 31.01 + численность на 31.12) / 2
```

## Что в числителе и знаменателе

Числитель — `sum(company_fire_flg)` за период. **Именно флаг, а не дата
увольнения:** `company_fire_dt` бывает проставлена на будущее, и такое
увольнение ещё может не состояться. Подробно — в `t-emp-structure`,
раздел «Факт увольнения — только `company_fire_flg`».
Знаменатель — средняя численность, а **не** численность на конец периода.

## Гранулярность и период

Месяц. Есть два варианта: MTD (за месяц) и YTD (накопленная с начала года).

**Критическое требование к периоду: данные берутся на один месяц шире
запрошенного.** Для текучести с января 2025 нужна численность за декабрь 2024 —
иначе `lag()` вернёт `NULL` и январь останется без знаменателя.

Фильтр периода применяется **после** оконной функции. Если обрезать данные
в том же запросе, где считается `lag()`, граница съест предыдущий месяц:

```sql
-- ❌ НЕПРАВИЛЬНО: WHERE применяется ДО lag(), декабрь отрезан
select
    month_dt
    , lag(hc_cnt) over (partition by unit_rk order by month_dt) as prev_month_hc
from monthly_headcount
where month_dt >= date '2026-01-01'  -- для января prev_month_hc = NULL
```

## Где считается

`t-emp-structure`. MTD:

```sql
with pre as (
    select
        date_trunc('month', m.business_dt)::date as business_dt  -- месяц
        , count(*) filter (where last_day_of_month_flg = 1 or m.last_day_flg = 1) as cnt_emp  -- численность
        , sum(m.company_fire_flg) as fire_emp  -- уволенные
    from prod_v_emart.mdm_employee_structure_d m
    where m.business_dt between '2025-09-30' and '2026-03-31'  -- период + 1 месяц
      and m.active_employee_flg = 1
    group by 1
)
, avg_cnt as (
    select
        *
        , (cnt_emp + lag(cnt_emp) over (order by business_dt)) / 2.0 as avg_cnt_emp  -- средняя
    from pre
)
select
    business_dt  -- месяц
    , fire_emp  -- уволенные
    , avg_cnt_emp  -- средняя численность
    , (fire_emp / avg_cnt_emp * 100)::numeric(23,2) as turnover  -- текучесть, %
from avg_cnt
where business_dt >= '2025-10-01';  -- целевой период, фильтр ПОСЛЕ lag()
```

## Regrettable и non-regrettable

Разделение оттока на «жалеем» и «не жалеем» по инициативе увольнения, стажу,
грейду и оценке производительности.

**Расчёт не подтверждён.** Он опирается на поля `initiative_source_nm`,
`mltiip_flg`, `emp_grade_cd`, `performance_rating`, наличие которых
в `t-emp-structure` не проверено. Перед использованием нужен `get_table_info`;
если полей нет — метрику в этом виде посчитать нельзя. До подтверждения
не выдавать заказчику цифру regrettable как факт.

## Чем НЕ является

Не «количество уволенных» — это абсолютный отток, числитель без знаменателя.
Не retention: retention считает остаток, текучесть — выбытие.

## Частые расхождения

**Январь показывает `NULL` или аномальную текучесть.** Не расширен период
на месяц назад либо фильтр применён до `lag()`.

**Текучесть выше ожидаемой.** Проверить, не взята ли численность на конец
периода вместо средней: на растущей численности это завышает результат.

**Отток за период почти нулевой.** Признак `last_day_flg = 1` в запросе
за период или фильтра по `company_fire_dt` вместо `business_dt`.
