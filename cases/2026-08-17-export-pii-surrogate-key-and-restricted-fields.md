# ФИО/логин, город проживания, размер одежды — три разных случая при выгрузке

## Вопрос дословно

> Обращение по теме «Выгрузка данных», домен численности (`headcount-structure`).

## Ответ

> Чего не будет:
>
> ФИО и логин — это персональные данные, в выгрузки не отдаются. Вместо них
> предлагаю суррогатный ключ сотрудника (мастер ID).
> Город проживания — это поле есть в данных, но оно может оказаться закрытым
> группами доступа — требуется согласование. По умолчанию не выгружается.
> Размер одежды — такого поля в нашем каталоге нет, выгрузить не сможем. Если
> нужно, уточните, какой источник используете.
> Все эти данные можно предоставить, для этого необходимы доп. согласования.

## Чего не хватило

Чек-лист согласования (`export-playbook.md`, шаг 3) уже требовал не выгружать
ПДн и предлагать суррогатный ключ, но не разводил три разных случая, которые
на практике идут в одном обращении:

1. поле есть, но всегда закрыто (ФИО, логин) → суррогатный ключ, без вариантов;
2. поле есть, но закрыто группами доступа не всегда → согласование, по
   умолчанию не отдаём;
3. поля с таким смыслом в каталоге нет вовсе → не подставлять похожее поле по
   созвучию, прямо говорить «такого поля нет».

Перенесено в `kb/process/export-playbook.md`.
