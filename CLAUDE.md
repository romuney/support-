# CLAUDE.md

Карта репозитория для сессий Claude Code. Прочитать до первой правки.

## Что где лежит

Четыре папки верхнего уровня, и у каждой свой хозяин. Пятая — `context/` —
не рабочая: в неё сложено то, из чего рабочее собирали.

| Папка | Что внутри | Правила |
|---|---|---|
| `executive-support/` | **Вся база знаний**: `kb/`, `cases/`, `exports/`, `templates/`, `docs/`, валидатор | Свои правила — [`executive-support/CLAUDE.md`](executive-support/CLAUDE.md). Читать его целиком перед любой правкой внутри |
| `bot/` | Воркфлоу n8n и промпты бота: ядро, адаптеры каналов, DD Lookup, DD Recon | JSON руками не правится — собирается скриптами `build_*.py` |
| `telemetry/` | Сбор оценок, калибровка, витрина обращений | То же: сборка скриптами, не руками |
| `иконки/` | Эмодзи-пак и GIF бота: промпты генерации, прогон через Nano Banana (`generate.py`) и нарезка | Ключ к Gemini API — из `.env`, в репозиторий не кладётся |
| `context/` | Разборы прогонов, выгрузки канала, handoff'ы, спецификация DD (`openapi`), `AGENTS.md` | **Сырьё, а не источник правды.** В контекст бота не подаётся, правками отсюда не руководствуемся |

Корневой `RUNBOOK.md` — инструкция по работе с ботом, телеметрией и git.

## Одна копия базы знаний

База знаний живёт **только** в `executive-support/`. Второй копии нет намеренно.

Раньше их было две — `executive-support/` и папка `kb/` в корне, — и они
разъехались на 14 сущностей и целый домен: в корне были отчёты и домен
`meetings`, в `executive-support/` их не было. Тесты мастеров при этом
оставались зелёными, потому что список путей молча брал первый существующий
файл, а первым стояла устаревшая копия.

Отсюда правило: **путь к реестру ровно один** — `executive-support/kb/index.md`,
и в `bot/test_pipeline.mjs`, `bot/test_adapters.mjs`, `bot/build_dd_recon.py`
он записан списком из одного элемента. Не восстанавливать фолбэк: копию
чинят удалением, а не вторым путём в списке.

## Что запустить перед коммитом

```bash
cd executive-support && python3 validate_kb.py   # правки в kb/
cd bot && for t in pipeline adapters shapers recon; do node test_$t.mjs || break; done
cd telemetry && node test_telemetry.mjs
```

Наборы перечислены циклом, а не аргументами одной команды: `node a.mjs b.mjs`
запускает ТОЛЬКО `a.mjs`, остальное уезжает в `process.argv`. Здесь так и было
написано — и три набора из четырёх не запускались вовсе.

Правки в `kb/` — валидатор обязателен: он ловит то, что глазами не видно
(разъехавшиеся алиасы, мастера не в своём домене, расхождение фронтматтера
и реестра). Правки в `bot/` или `telemetry/` — пересобрать воркфлоу
соответствующим `build_*.py` и прогнать тесты обеих папок.

## Ноды n8n не додумываются

Разбор 02.09. Три догадки подряд — номер цвета заметки, семантика двух каналов
в одном фильтре, «стухшая регистрация вебхука» — стоили вечера. Все три
проверялись за минуты, потому что n8n открыт, а у сессии есть поиск и чтение
страниц. Ими не пользовались.

Правило: **перед тем как собрать или объяснить узел, смотрят источник.**

- Стандартный узел (`n8n-nodes-base.*` из апстрима) — исходник в
  `github.com/n8n-io/n8n`, `packages/nodes-base/nodes/<Имя>/`. Настройки узла
  (`retryOnFail`, `onError`, …) и палитра заметок — там же. `docs.n8n.io`
  и `community.n8n.io` из этой среды закрыты прокси, `raw.githubusercontent.com`
  открыт; `api.github.com` без токена отдаёт 403, страницы деревьев — 404,
  поэтому путь к файлу берут из известного коммита или поиска, а не гадают.
- Community-пакет — его репозиторий; ветка по умолчанию это `main` или `master`,
  и это единственная допустимая пара попыток.
- Узел, которого нет ни в апстриме, ни в пакетах (здесь: `mattermostTrigger` v2
  с `postedFilters`, `CUSTOM.*`), — **только форма из живого снимка n8n**
  (`Time examples.json`). Расширение формы сверх снимка — гипотеза: помечается
  словом «не подтверждено», и к импорту прикладывается способ проверить
  снимком. Два канала в одном фильтре были ровно таким расширением.

Что уже установлено и не требует повторного поиска: в апстриме n8n триггера
Mattermost нет, есть только узел действий. Три публичных community-триггера
(myluffe, @hoangnvpck, @designveloper) прочитаны из tarball'ов
`registry.npmjs.org` — этот хост открыт, а `www.npmjs.com` и CDN закрыты:
все три — WebSocket с клиентской фильтрацией и реконнектом; каналы, где есть,
задаются ПО ID (`channelIds.includes(channel_id)`). Ни в одном нет
`postedFilters` / `nameAuto` / `isDirectMessage` — узел этого инстанса
(`mattermostTrigger` v2) публичного исходника не имеет. «Молчит при
Published» у такого триггера — оборвавшийся сокет, а не вебхук.

## Что действует во всём репозитории

**Персональные данные.** ФИО, телефоны, почты, даты рождения, зарплаты
конкретных людей не попадают в репозиторий никогда — ни в кейсах, ни
в примерах, ни в SQL, ни в комментариях к коду. Только суррогатные ключи
(`candidate_sk`) и роли. Это относится и к выдуманным примерам.

**Секретов в репозитории нет и не заводим.** Токены, ключи и конфиги CLI —
мимо git, в `.env` (он в `.gitignore`).

**Именование.** Латиница, строчные, дефисы. Ни пробелов, ни кириллицы,
ни подчёркиваний в именах файлов и папок. Исключения — исторические:
`иконки/` и файлы в `context/`.

**Ссылки.** Внутренние — относительными путями, и они обязаны резолвиться.
Внешние на треды и дашборды — плейсхолдеры, настоящих URL в репозитории нет.
