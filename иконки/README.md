# Эмодзи-пак бота поддержки

Реакции и иконки на базе основной картинки бота (`bulli-ref.png`).
Здесь лежат **задания для Nano Banana** и скрипты нарезки. Сами PNG/GIF
кладутся в `out/` и оттуда заливаются в Mattermost.

**Спецификация пака ровно одна, и это `prompt-each.md`.** До 06.09 живых было
две: `prompt-pack-v2.md` и `prompt-each.md` описывали разный v2 — плоское

дизайнами. Не заводить вторую копию задания: расходятся они молча, а видно
это уже на залитых иконках.

по 25–32 КБ при пределе Mattermost в 1 МБ. Разбор прогона и чем он
разошёлся с промптом — в `prompt-pack.md`, раздел «Что пришло».

## Порядок работы

1. Отдать Nano Banana задание из [`prompt-each.md`](prompt-each.md), приложив
   **два** файла: `bulli-ref.png` (исходный портрет) и `bully-style-ref.png`
   (кадр из принятого листа анимации — тот стиль, который дошёл до Mattermost
   живым). **Просить максимальное разрешение и PNG**, не JPEG: JPEG мылит
   границу силуэта, и вырезание фона даёт кайму.

   Всё это делает [`generate.py`](generate.py) одной командой — он берёт промпт
   из самого задания (первый огороженный блок файла), прикладывает оба
   референса и просит 2K PNG:

   **Пак идёт листами, а не по картинке на иконку:** платится за картинку,
   и лист из шести — это одна оплаченная вместо шести. Внутри листа ячейки
   рисуются в одном проходе, поэтому и персонаж выходит один и тот же.
   Шесть — потолок: на двенадцати модель теряет надпись CROSS и рамку
   плашки (замер — в разделе «Что пришло с прогона 2026-09-07 (листами)»).

   ```
   # лист из шести, принятый эталон ЕДИНСТВЕННЫМ референсом
   python3 generate.py prompt-each.md --grid 3x2 --aspect 3:2 --size 4K \
       --only bully_ready,bully_fail,bully_hi,bully_search,bully_high,bully_mid \
       --no-ref --anchor out-badge/bully_done.png --out raw-badge/sheet-a6.png
   # черновой прогон подешевле
   python3 generate.py prompt-each.md --grid 3x2 --aspect 3:2 --size 1K \
       --only ... --out draft.png --model gemini-3.1-flash-image
   # посмотреть, что уйдёт, и не отправлять
   python3 generate.py prompt-each.md --grid 3x2 --only ... --out x.png --dry-run
   ```

   **`--no-ref` не опечатка.** С двумя портретами без плашки впереди принятая
   иконка идёт третьей, и плашку модель рисует по описанию словами, а не
   по ней: тонкий контур вместо толстой рамки. Единственным референсом
   она держит и рамку, и позу, и уши.

   Промпт живёт в markdown и никуда не копируется: вторая копия разъехалась бы
   с заданием молча. Скрипт печатает первую строку взятого блока — если взялся
   не тот, это видно до оплаты прогона, а не по странной картинке.

   Веб-интерфейс [AI Studio](https://aistudio.google.com/) остаётся рабочим
   способом: там удобнее доводить промпт в диалоге. Скрипт нужен для
   повторяемого прогона готового задания.
2. Что осталось за листом — по одному стикеру за прогон из
   `prompt-stickers.md`: первая попытка листом снесла стиль, пришёл плоский
   рисунок с фактурой бумаги вместо 3D-рендера. Разбор — в самом файле.
3. Прислать полученные картинки сюда. Нарезка и сборка:

```
# лист: имена по порядку ячеек, тем же порядком, что в --only
python3 slice_grid.py raw-badge/sheet-a6.png --cols 3 --rows 2 \
    --names bully_ready,bully_fail,bully_hi,bully_search,bully_high,bully_mid \
    --out out-badge/
# лист лап — в столбик
python3 slice_grid.py raw-badge/sheet-lapy.png --cols 1 --rows 3 \
    --names bully_helpful,bully_not_helpful,bully_detail --out out-badge/
# по одному стикеру
python3 slice_grid.py bully_yes.png --cols 1 --rows 1 --names bully_yes --out out/
# если всё же вышло листом 4x4 или 3x3
python3 slice_grid.py sheet-d.png --cols 4 --rows 4 --names names-c.txt --out out/
python3 slice_grid.py sheet-a.png --names names-a.txt --out out/
# анимация — всегда листом, иначе кадры не совпадут по камере
python3 make_gif.py typing-sheet.png --out out/bulli_typing.gif --ms 80
```

4. **Проверить пак до заливки** — [`check_pack.py`](check_pack.py):

```
python3 check_pack.py out-badge --sheets review/
```

   Числом он ловит состав и формат, иконку без плашки (то есть попавшую
   в пак из другого прогона), выпавшую по размеру плашку, срез по краю
   кадра, остатки серого фона и пары, неразличимые на 21 px. Контактные
   листы в `--sheets` показывают то, что числом не берётся: одинаковый ли
   персонаж, стоят ли уши, крупная ли морда в плашке. Смотреть оба листа:
   `sheet-128.png` — как в списке эмодзи, `sheet-reaction.png` — как
   в плашке реакции, на светлой и тёмной теме.

   Проверка стоит между нарезкой и заливкой не для порядка: заливка
   пака — это шестнадцать раз «удалить имя и завести заново» руками,
   и второй заход по тем же именам никому не нужен.

5. Залить в Mattermost: **Main menu → Custom Emoji → Add Custom Emoji**.
   Картинку у существующего эмодзи Mattermost заменить не даёт: чтобы залить
   v2 под теми же именами, каждое имя сначала удаляют, потом заводят заново —
   **по одному**, иначе посты с этой реакцией на время покажут голый
   `:bully_done:`.
6. Подставить имена в код — **отдельным коммитом и не всё подряд**:
   разбор, что чем заменяется и что при этом ломается молча, — в разделе
   «Где это живёт в коде» файла [`prompt-pack.md`](prompt-pack.md).

## Ключ к API

`generate.py` ходит в Gemini API от имени ключа. **Ключа в репозитории нет
и не будет** — он читается из `.env` в корне репозитория (файл в `.gitignore`)
или из переменной окружения:

```
# support-/.env
GEMINI_API_KEY=<ключ>
```

Где взять:

1. [Google AI Studio → API keys](https://aistudio.google.com/apikey) — войти
   гугл-аккаунтом, **Create API key**, выбрать проект Google Cloud или дать
   создать новый. Это самый короткий путь.
2. Тот же ключ виден в [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials),
   если проектом уже управляют оттуда.
3. Биллинг проекта включается в [Cloud Console → Billing](https://console.cloud.google.com/billing).

Документация и цены — [обзор Gemini API](https://ai.google.dev/gemini-api/docs),
[генерация картинок](https://ai.google.dev/gemini-api/docs/image-generation),
[тарифы](https://ai.google.dev/gemini-api/docs/pricing).

**Генерация картинок в бесплатный тариф не входит** — под неё нужен проект
с включённым биллингом. Порядок цены за одну картинку: Nano Banana Pro
(`gemini-3-pro-image`) — десятки центов, дороже на 4K; флешевые модели
(`gemini-3.1-flash-image`, `gemini-2.5-flash-image`) — единицы центов.
Точные цифры и статус моделей смотреть на странице тарифов: `gemini-2.5-flash-image`
объявлена к отключению, и держать её как запасную стоит только до тех пор,
пока страница моделей это позволяет.

Один лист пака 4×4 — это **один** прогон, а поштучная пачка (`--each`) —
шестнадцать, то есть примерно во столько же раз дороже. Платят за это полным
разрешением на каждую морду и за возможность перекатить одну иконку вместо
всех; чем это лучше и хуже листа — в [`prompt-each.md`](prompt-each.md).
Готовое `--each` не перегенерирует: чтобы перекатить одну, зовут
`--only <имя> --force`. **Не удалять файл руками:** скрипт пишет картинку
только после того, как она пришла, поэтому `--force` при обрыве оставляет
старую, а удаление теряет её насовсем.

## Фон прозрачный, а не белый

Соблазн сгенерировать сразу на белом — интерфейс Тайма белый, и белое
на белом сойдётся. Не сойдётся в трёх местах, и первое из них главное:

| где | что будет с белым фоном |
|---|---|
| **плашка реакции** | она рисуется на тонированном фоне — белый квадрат виден коробкой даже на светлой теме |
| тёмная тема | её выбирает сам сотрудник, и там белый прямоугольник вокруг персонажа |
| наведение на сообщение, подсветка поиска, упоминание | строка подсвечивается, фон эмодзи — нет |

Прозрачный PNG на белой теме и есть «белое на белом», а в остальных трёх
случаях он единственный, который работает. Плашка реакции решает: именно
в ней эмодзи и живёт.

Генерировать при этом надо на СЕРОМ, а не на белом или прозрачном:
шерсть бульдожки кремовая, почти белая, и заливка с белого фона протекла бы
внутрь персонажа. Прозрачный фон Nano Banana не отдаёт вовсе.

Фон снимается по трём признакам сразу — пиксель **нейтрально-серый**,
**ровный** (без перепада яркости вокруг) и **связан с краем ячейки**, —
поэтому **никакой обводки вокруг персонажа не нужно**: серый фон отделяется
от кремовой шерсти сам, без каймы на тёмной теме — проверено прогоном пака.
Белая обводка стояла в первой версии промпта и оказалась одной из причин
слома стиля.

Каждый признак добавлен после конкретного брака, и ни один не лишний:
без насыщенности заливка либо выедала собаке грудь, либо оставляла серые
лоскуты в вогнутых местах; без ровности она уходила в СЕРУЮ кепку по шву
и оставляла в ней прозрачные трещины — на светлой теме белые чёрточки,
на тёмной чёрные. Замеры и алгоритм — в докстроке `sheet.key_background`;
трогать пороги без такого же замера не стоит.

В v2 у тринадцати иконок прозрачным остаётся только то, что снаружи лучей,
а у трёх с лапой — всё вокруг силуэта, как в v1. Три довода выше от этого
не слабеют: белый квадрат по углам был бы виден ровно так же.

Отсюда единственное ограничение, которое v2 накладывает на палитру:
**диск не может быть нейтрально-серым.** Маска фона — это «серый И ровный
И связан с краем», и серый диск попадает в неё целиком. Замер синтетической
ячейкой: с жёстким краем серый диск выживает (заливку останавливает перепад
яркости на границе), но у рендера край мягкий, и на размытии 1.5–3 px диски
`#8A8A8A` и `#A0A0A0` вырезаются вместе с фоном, а цветные — нет. Порог:
разница между максимальным и минимальным каналом не меньше 30. Заодно диск
чинит светло-серую кепку `bully_unknown`, которая в v1 шла трещинами: внутри
диска заливка до неё не доходит. Таблицы замеров — в
[`prompt-pack-v2.md`](prompt-pack-v2.md).

**Заливать уже в 128×128.** Больший файл сервер пережмёт сам, и у анимации
это чаще всего означает потерянные кадры или испорченную прозрачность.
Скрипты отдают ровно 128×128 с альфой.

## Состав пака

Имена — с префиксом `bully_`, чтобы в списке эмодзи они лежали вместе
и не конфликтовали со стандартными.

**Префикс ровно один, и это `bully_`.** Раньше пак назывался `bulli_*`,
а единственная реально залитая иконка — `bully_work`; из двух написаний
живым было второе, и в списке эмодзи Тайма два семейства на одну собаку
означали бы, что `:bull` подсказывает половину пака. Планы переименованы
под живое имя; комментарий про расхождение у `WORK_EMOJI` в
`bot/build_time_flows.py` снят при подстановке имён 02.09.

### Пачка C — основной пак, ровно под код

**Живой пак ровно один, и это тот, что залит в Mattermost.** Остальные папки —
кандидаты и история; заменяется пак только целиком, иначе в списке эмодзи
окажутся две разные собаки.

| папка | прогон | дизайн | состояние |
|---|---|---|---|
| `out/` | 02.09, лист `sheet-c.jpg` | v1: морда на прозрачном, цвет несёт кепка | **залито в Mattermost**, это то, что видят люди |
| `out-each/` | 04.09, по картинке за прогон | тот же v1, без плашки | кандидат, не залит. На 21 px хуже обоих: 41 неразличимая пара из 120 против 6–7 |
| `out-badge/` | 07.09, тремя листами | **v2: круглая плашка, обратная связь лапой** | **готов, ошибок у `check_pack.py` нет.** Не залит. `bully_done` — эталон пака, взят из прогона 06.09 и не перегенерируется: он задаёт позу, кадр и плашку с яркой рамкой, остальные пятнадцать прогнаны с ним в якоре |

Три папки с тремя дизайнами — это и есть та беда, из-за которой пак смотрят
`check_pack.py` и заливают один раз. Когда новый пак принят и залит, две
лишние папки удаляются, и остаётся одна.

Основная пачка: шестнадцать иконок, у каждой есть место в коде.
Задание, позы, цвета кепок и разбор замен — [`prompt-pack.md`](prompt-pack.md),
имена по порядку ячеек — `names-c.txt`.

| строка листа | эмодзи |
|---|---|
| цикл обращения | `bully_ready`, `bully_done`, `bully_fail`, `bully_hi` |
| оценка ответа | `bully_helpful`, `bully_not_helpful`, `bully_detail`, `bully_search` |
| светофор уверенности | `bully_high`, `bully_mid`, `bully_none`, `bully_unknown` |
| служебные маркеры | `bully_flag`, `bully_warn`, `bully_lock`, `bully_expert` |

Цвет в этой пачке несёт смысл: зелёный — ок, янтарный — с оговорками,
красный — не ок, светло-серый — непонятно, синий — просто работа. Предмет
в кадре отвечает на «что случилось», цвет — на «как прошло».

**В v1 цвет нёс только кепку, и в v2 под персонажа встаёт ещё диск с лучами
того же цвета.** Причина в размере: реакция рисуется не в 128 px, а примерно
в 22, и кепка на таком размере — две-три точки, зелёная от жёлтой
не отличается. Диск с лучами заливает почти весь кадр и уменьшение
переживает; кепка цвет сохраняет и подтверждает вердикт вблизи. Тонов
поэтому три: диск тёмный, лучи средние, кепка светлая — тон в тон кепка
на диске растворяется.

Там же, в v2, три иконки оценки (`bully_helpful`, `bully_not_helpful`,
`bully_detail`) стали **лапой бульдожки** с привычным жестом — палец вверх,
палец вниз, карандаш — вместо морды с лапой в углу: на кнопке рядом
с подписью портрет не читается. Диска у них нет, лапа занимает весь кадр
сама. Разбор и палитра — в [`prompt-each.md`](prompt-each.md).

### Пачка A — процесс обращения

Написана до пачки C, по представлению о том, что пригодится. Пересечения
с листом (`bully_ready`, `bully_done`, `bully_fail`, `bully_search`,
`bully_lock`, `bully_expert`) генерировать **один раз** — оттуда, откуда
пришёл принятый стиль, а не дважды.

| эмодзи | состояние | где применяется |
|---|---|---|
| `bully_work` | **GIF**: стучит лапами по клавиатуре | взято в работу / бот думает — ставится сразу на сообщение с тегом и в личке. Залито первым; файл на диске — `out/bulli_typing.gif` |
| `bully_ready` | «ответ готов», гордая поза | снимается `bully_work`, ставится это — **в коде** с 02.09, оба адаптера |
| `bully_yes` | палец вверх, подмигивает | высокая уверенность |
| `bully_hmm` | пожимает плечами | средняя уверенность |
| `bully_noidea` | лапы разведены, вопрос | `нет ответа` |
| `bully_done` | зелёная галка | решено — **в словаре телеметрии** рядом с `done_checkmark`, старое имя остаётся |
| `bully_fail` | красный крест | закрыто нерешённым — то же рядом с `im_red_cross` |
| `bully_search` | лупа | пошёл в каталог DD |
| `bully_lock` | замок | согласование ИБ / закрытые поля |
| `bully_expert` | указывает лапой, стрелка | сработал маршрут из таблицы «Маршруты» |

Три верхние строки пачки A и светофор пачки C — про одно и то же, но
по-разному: `bully_yes` / `bully_hmm` / `bully_noidea` показывают уверенность
позой, `bully_high` / `bully_mid` / `bully_none` — цветом кепки. Выбрать
надо одно из двух и не заливать оба набора: в шапке ответа стоит один
значок, и два словаря на одно место — это молча разъехавшийся смысл.
